## Problem Statement

`backend/app/indicators/levels.py::_extreme_levels(df)` produces the "前高 / 前低" / "60日新高 / 250日新高" group that the chart's `LEVEL_TYPES['extreme']` consumer renders as horizontal markLines (see `frontend/src/components/stock-analysis/AnalysisKChart.tsx:50`). Every `/api/stock-analysis/levels?symbol=…` request that lands on the dashboard (or that the `useStockAnalysis` React-Query cache refetches) invokes it.

Today, `_extreme_levels` runs two Python-side loops over the input:

1. **60/250 day windowed extremes** — `df.tail(60)["high"].max()` / `df.tail(60)["low"].min()` (and the same for 250 days). Two passes per window over up to 250 rows each. Total: `O(2 × (60 + 250))` ops, mostly small.
2. **Recent swing detection** — `for i in range(win, len(highs) - win): if highs[i] == max(highs[i - win:i + win + 1])`. **This is the wall**: for each bar it allocates a fresh slice of length `2*win+1`, runs Python's builtin `max` over it, and does equality check. Per call: `N × 2*win+1` allocations + comparisons. For 240-day, `win=5`: ~2,640 slice allocations + `max()` calls.

The combined function takes 0.1 ms on a 240-day fixture (bench 2026-10-19). Absolute latency is small, but the **algorithmic shape** (per-bar slice allocation + `max()`) is the same kind of Python-interpreter wall that the previous spec (`_support_resistance`) moved to Rust. Path A-2 follows the same seam-and-adapter pattern as Spec 0001 to retire that wall and free the second non-trivial hot loop in the levels seam package.

## Solution

Move the **compute core** of `_extreme_levels` (60/250 windowed extremes + per-bar swing detection) into a single Rust kernel `tf_rs_indicators.extreme_levels(df, windows, swing_win)` that returns a `polars.DataFrame` of the same height with three primitive types:
- `swing_high: Boolean` — per-bar local-max indicator (true at index `i` iff `highs[i] == max(highs[i-win..i+win+1])`)
- `swing_low: Boolean` — per-bar local-min indicator (symmetric)
- `extreme_<w>_high: Float64` and `extreme_<w>_low: Float64` — broadcast scalars (same value on every row) carrying `max(highs.tail(w))` / `min(lows.tail(w))`. Polars 0.55 broadcasts the value by writing it on every row of a `Float64Chunked` (1-row scalar broadcast).

The Python adapter at `levels.py::_extreme_levels` is a thin wrapper:

```python
def _extreme_levels(df: pl.DataFrame) -> list[dict]:
    try:
        from tf_rs_indicators import extreme_levels as _rs_extreme_levels
    except ImportError:
        return _py_extreme_levels(df)                  # pure-Python fallback

    out_df = _rs_extreme_levels(df, [60, 250], 5)
    sh = out_df.get_column("swing_high").to_list()
    sl = out_df.get_column("swing_low").to_list()
    highs = df["high"].to_list(); lows = df["low"].to_list()
    close = float(df.tail(1)["close"][0])
    return _reduce_extreme_levels(sh, sl, highs, lows, close,
                                   out_df["extreme_60_high"][0],
                                   out_df["extreme_60_low"][0],
                                   out_df["extreme_250_high"][0],
                                   out_df["extreme_250_low"][0])
```

The 60/250 reductions plus the swing aggregation are extracted into shared helpers `_py_extreme_levels` (pure-Python reference) and `_reduce_extreme_levels` (Python reduce on the Rust output) so the reduce code is shared by both paths.

## User Stories

1. As a chart user, I want `_extreme_levels` to render in well under 1 ms for a 240-day A-share, so that opening levels panels feels instant.
2. As a chart user, I want the rendered 前高 / 前低 / 60日新高 / 250日新高 to be **bit-identical** to today's Python implementation, so that markLine positions, AI prompt context, and historical screenshots don't shift.
3. As the AI stock analysis module, I want `levels._extreme_levels(df)` to keep returning `list[dict]` with the same `value/label/type/side/strength` keys, so the AI prompt template doesn't need a code change.
4. As a chart user, I want the function to **degrade gracefully** to the pure-Python path on machines without the Rust wheel, so CI / desktop builds without `tf_rs_indicators` still produce a chart.
5. As a regression tester, I want a `pytest -k extreme_levels_seam` suite that fails loudly if the Rust kernel drifts from the Python reference, so algorithm drift is caught pre-merge.
6. As a regression tester, I want `cargo test -p tf-rs-indicators -- extreme_levels` to run without Python, so the kernel can be benchmarked in isolation.
7. As a maintainer, I want the Python wrapper at `levels.py::_extreme_levels` to stay small (≤ 40 lines), so the public-API contract is auditable.
8. As a Rust contributor, I want the kernel in its own `crates/indicators/src/extreme_levels.rs` module (not hidden inside `levels.rs`), so each indicator slot follows the `crates/indicators/src/<name>.rs` template from ADR-0001.
9. As a maintainer of vendored Polars patches (TF-RS-1), I want the kernel to only depend on `Float64Chunked::to_vec` / `BooleanChunked` / `PyDataFrame` round-trip (already covered by the vendored crate patches), so a future polars 0.55.3+ bump doesn't silently break extreme_levels.
10. As a future indicator author, I want the seam test scaffolding (`backend/tests/test_rs_<name>_seam.py` + try-import fallback) to apply to `_extreme_levels` as documented in Spec 0001 §13, so the second indicator is a 1-day exercise, not a fresh design.
11. As a performance engineer, I want one Rust pass to compute all of {60d_high, 60d_low, 250d_high, 250d_low, per-bar swing highs, per-bar swing lows} in a single `for i in 0..n` loop, so PyO3 boundary cost is paid exactly once per call.
12. As a maintainer, I want the swing-detection Python `== max(...)` semantics (ties mark all bars) to be preserved exactly — including the `i in [win, n-win)` skip of the boundary bars, so that the algorithm is bit-identical even on fixtures with consecutive equal closes.

### Algorithm (Rust)

Single pass over `Vec<f64>`:

```rust
#[pyfunction]
pub fn extreme_levels(df: PyDataFrame, windows: Vec<u32>, swing_win: u32) -> PyResult<PyDataFrame> {
    let df = df.into_inner();
    let highs = df.column("high")?.f64()?.to_vec();
    let lows  = df.column("low")?.f64()?.to_vec();
    let n = highs.len();

    // 60 / 250 extremes: scan once, track running max/min per window
    let mut extremes: HashMap<u32, (f64, f64)> = HashMap::new();
    for &w in &windows {
        let start = n.saturating_sub(w as usize);
        let (mut hmax, mut lmin) = (f64::NEG_INFINITY, f64::INFINITY);
        for i in start..n {
            if let Some(h) = highs[i] { if h > hmax { hmax = h; } }
            if let Some(l) = lows[i]  { if l < lmin { lmin = l; } }
        }
        extremes.insert(w, (hmax, lmin));
    }

    // Per-bar swing detection (tie-aware)
    let win = swing_win as usize;
    let mut swing_high = vec![false; n];
    let mut swing_low  = vec![false; n];
    if n > 2 * win {
        for i in win..(n - win) {
            let (h, l) = match (highs[i], lows[i]) {
                (Some(h), Some(l)) => (h, l),
                _ => continue,
            };
            // local max iff h >= every neighbor in [i-win, i+win]
            let lo = i - win; let hi = i + win + 1;
            swing_high[i] = (lo..hi).all(|j| j == i || highs[j].map_or(true, |x| x <= h));
            swing_low[i]  = (lo..hi).all(|j| j == i || lows[j].map_or(true,  |x| x >= l));
        }
    }

    // Build output DataFrame: passthrough cols + swing booleans + per-window broadcast columns
    let mut out = df.clone();
    out.push_column(BooleanChunked::new(PlSmallStr::from_static("swing_high"), swing_high).into_column())?;
    out.push_column(BooleanChunked::new(PlSmallStr::from_static("swing_low"),  swing_low).into_column())?;
    for &w in &windows {
        let (h, l) = extremes[&w];
        let col_h = Float64Chunked::from_vec(PlSmallStr::from(format!("extreme_{}_high", w)), vec![h; n]).into_column();
        let col_l = Float64Chunked::from_vec(PlSmallStr::from(format!("extreme_{}_low",  w)), vec![l; n]).into_column();
        out.push_column(col_h)?;
        out.push_column(col_l)?;
    }
    Ok(PyDataFrame(out))
}
```

Notes:
- Tie-aware `swing_*`: `(lo..hi).all(|j| j == i || highs[j] <= h)` matches Python's `highs[i] == max(highs[i - win:i + win + 1])` exactly — every bar that ties for max gets marked.
- Boundary skip: `for i in win..(n - win)` matches Python's `range(win, len(highs) - win)`.
- The 4 extremes broadcast as Float64 columns with the same value on every row; the Python adapter reads `[0]` (or `[-1]`, identical) for each.
- No-op contract: if df.height == 0, the kernel still returns a 0-row DataFrame with the broadcast columns (1 null each); the adapter checks `df.is_empty()` and returns `[]`.

### Pre-implementation research (Ticket 01)

- `docs/research/extreme-levels-rust-api.md` (Ticket 01) — survey of `polars::series::rolling_max` / `rolling_min` (with `options: RollingOptionsFixedWindow`) on `Float64Chunked`, plus sketch of the pure-Rust single-pass algorithm. Verdict: **Approach A** (same as Spec 0001 — `to_vec()` once, then single Rust loop, no Polars expressions in the hot path). The windowed extremes can technically be expressed as `pl.col("high").rolling_max(60).tail(1)`, but pulling those into Rust saves the PyO3 round-trip and lets the swing scan share the same `highs`/`lows` slices in one cache-friendly pass.
- Open question §3 of the research note (for the implementer): the parity-test fixture (240-day) needs to be regenerated by running the Python reference once with `random.seed(42)`. The throwaway fixture `crates/indicators/examples/fixtures/extreme_levels_30d.parquet` is for fast iteration only.

### Python wrapper (thin adapter)

The Python adapter extracts the reduce tail (the 60/250 emission + swing aggregation) into a shared helper `_reduce_extreme_levels` so both the pure-Python reference and the Rust-via-adapter path route through it:

```python
def _reduce_extreme_levels(
    sh: list[bool], sl: list[bool],
    highs: list[float | None], lows: list[float | None],
    close: float,
    ext60h: float, ext60l: float,
    ext250h: float, ext250l: float,
) -> list[dict]:
    out: list[dict] = []

    # 60/250 窗口极值 (共享逻辑, Python ref 直接算, Rust 路径从 kernel 读)
    for w, h, l in [(60, ext60h, ext60l), (250, ext250h, ext250l)]:
        if math.isfinite(h):
            out.append({"value": round(h, 2), "label": f"{w}日新高",
                        "type": "extreme", "side": "resistance", "strength": "strong"})
        if math.isfinite(l):
            out.append({"value": round(l, 2), "label": f"{w}日新低",
                        "type": "extreme", "side": "support", "strength": "strong"})

    # 近期 swing 高低点(从 kernel 拿到的 boolean series 过滤; ref 路径是逐 bar 自算)
    win = 5
    swing_highs = [float(highs[i]) for i in range(len(sh)) if sh[i] and highs[i] is not None]
    swing_lows  = [float(lows[i])  for i in range(len(sl)) if sl[i] and lows[i]  is not None]

    agg_h = _aggregate_levels(swing_highs, 0.01)
    agg_h = [v for v in agg_h if v > close * 1.001]
    agg_h.sort(key=lambda v: abs(v - close))
    for v in agg_h[:2]:
        out.append({"value": round(v, 2), "label": "前高",
                    "type": "extreme", "side": "resistance", "strength": "medium"})

    agg_l = _aggregate_levels(swing_lows, 0.01)
    agg_l = [v for v in agg_l if v < close * 0.999]
    agg_l.sort(key=lambda v: abs(v - close))
    for v in agg_l[:2]:
        out.append({"value": round(v, 2), "label": "前低",
                    "type": "extreme", "side": "support", "strength": "medium"})

    return out


def _extreme_levels(df: pl.DataFrame) -> list[dict]:
    """关键前高 / 前低 —— thin adapter (try Rust kernel, fall back to pure-Python)."""
    if df.is_empty():
        return []
    close = float(df.tail(1)["close"][0]) if "close" in df.columns else None
    try:
        from tf_rs_indicators import extreme_levels as _rs_extreme_levels
    except ImportError:
        return _py_extreme_levels(df)

    out_df = _rs_extreme_levels(df, [60, 250], 5)
    sh = out_df.get_column("swing_high").to_list()
    sl = out_df.get_column("swing_low").to_list()
    highs = df["high"].to_list()
    lows  = df["low"].to_list()
    return _reduce_extreme_levels(
        sh, sl, highs, lows, close,
        float(out_df["extreme_60_high"][0]),  float(out_df["extreme_60_low"][0]),
        float(out_df["extreme_250_high"][0]), float(out_df["extreme_250_low"][0]),
    )


def _py_extreme_levels(df: pl.DataFrame) -> list[dict]:
    """关键前高 / 前低 —— pure-Python reference. 1:1 port of the original loop."""
    if df.is_empty():
        return []
    close = float(df.tail(1)["close"][0]) if "close" in df.columns else None
    out: list[dict] = []

    # 60 / 250 窗口极值(直接算)
    ext: dict[int, tuple[float, float]] = {}
    for w in (60, 250):
        if df.height < w: continue
        sub = df.tail(w)
        ext[w] = (float(sub["high"].max()), float(sub["low"].min()))

    for w in (60, 250):
        if w not in ext: continue
        h, l = ext[w]
        if _ok(h):
            out.append({"value": round(h, 2), "label": f"{w}日新高",
                        "type": "extreme", "side": "resistance", "strength": "strong"})
        if _ok(l):
            out.append({"value": round(l, 2), "label": f"{w}日新低",
                        "type": "extreme", "side": "support", "strength": "strong"})

    # swing 检测(原 loop 1:1)
    win = 5
    if df.height > win * 2 and close:
        highs = df["high"].to_list(); lows = df["low"].to_list()
        sh = [False] * len(highs); sl = [False] * len(highs)
        for i in range(win, len(highs) - win):
            if _ok(highs[i]) and highs[i] == max(highs[i - win:i + win + 1]):
                sh[i] = True
            if _ok(lows[i]) and lows[i] == min(lows[i - win:i + win + 1]):
                sl[i] = True
        return out + _reduce_extreme_levels(
            sh, sl, highs, lows, close,
            ext[60][0], ext[60][1], ext[250][0], ext[250][1],
        )[len(out):]   # 60/250 已经算过, 跳过重复

    return out
```

Notes:
- `_reduce_extreme_levels` is the **shared reduce tail** — Python ref and Rust-via-adapter both route through it. Avoids duplicated logic.
- The try-import + fallback matches ADR-0002 §5 (try-import default, `extras = ["rs"]` opt-in).
- Boundary skip (`for i in range(win, len(highs) - win)`) and tie equality (`== max(...)`) preserved exactly.

### Seams (where the test lives)

- **Rust unit (`crates/indicators/src/extreme_levels.rs::tests`)**: 2 tests (hand-computed swing series on a 30-row fixture; graceful empty-df contract). Pattern follows `crates/indicators/src/levels.rs::tests`.
- **Python seam (`backend/tests/test_rs_extreme_levels_seam.py`)**: 4 tests in the style of `test_rs_levels_seam.py`:
  1. parity: kernel output == `_py_extreme_levels` output on a fixed 240-day fixture (bit-identical list[dict])
  2. fallback: `tf_rs_indicators` import-disabled → still returns dicts (via `_py_extreme_levels`)
  3. graceful no-op: empty df → returns `[]`
  4. dtype preservation: returned DataFrame has the same row count as input

The highest seam is "parity on a 240-day fixture" — bit-identical. This is the gate that holds the spec. If parity fails on the 240-day fixture, the spec is not done.

### Versioning & wheel

- `pyproject.toml` of the workspace root: no change. The wheel name (`tf_rs_indicators`), `pyo3-polars` features, and the `extras = ["rs"]` opt-in from ADR-0002 stay.

## Testing Decisions

- **What makes a good test for this spec**: bit-identical output of the kernel and the Python reference, on a 240-day fixture that captures typical A-share turnover distribution. The fixture is committed under `backend/tests/fixtures/extreme_levels_240d.parquet` (regenerated by running the Python reference once with `random.seed(42)`); the expected dict list is in `extreme_levels_240d.expected.json`.
- **Modules under test**: `crates/indicators/src/extreme_levels.rs` (Rust kernel) and the Python adapter path `app.indicators.levels._extreme_levels` (integration).
- **Prior art for similar tests**:
  - `crates/indicators/src/levels.rs::tests` — Rust unit test, pattern follows.
  - `backend/tests/test_rs_levels_seam.py` — 4-test dual-track pattern follows.
- **How the fixture is built** (one-time, then frozen):
  1. Capture the current Python `_py_extreme_levels` output on a 240-day A-share fixture.
  2. Save the fixture (parquet) + the expected output JSON next to it.
  3. Both the Python reference and the Rust kernel are run against the fixture; the test compares outputs.
  4. If the test fails, the expected output is **NOT** updated — a failing test means the kernel drifted.

## Out of Scope

- Migrating other functions in `levels.py` (`_pivot`, `_boll_channel`, `_keltner_*`, `_atr_stops`, `_gap_levels`, `_fibonacci_levels`, `_round_numbers`) — they are pure Polars expressions or list-of-floats arithmetic, no Python loop per row.
- Migrating `pipeline.py::compute_indicators` — 100% Polars expressions, already vectorised.
- Changing the chart frontend (no UI change, no API change).
- Windows installer / Inno Setup pipeline (Tauri build picks up the new wheel automatically via the existing `pyo3-polars` discovery path).
- Profile / performance budget verification (the perf claim is "well under 1 ms for 240-day fixture"; the bench harness to assert this is a follow-up spec, not this one).
- Switching the default fall-back policy. ADR-0002 §5 holds: try-import default, opt-in via `uv sync --extra rs`. This spec doesn't change it.
- Per-bar swing metadata stored as a Polars column on the output (currently it's discarded after the adapter reads it; future work could surface it for the chart to draw small triangle markers).
